# GLOSSARY

Словарь терминов проекта «Календарь звонков». Используйте эти формулировки
в коде, тестах, документации и ADR, чтобы говорить об одном и том же
одинаково.

| Термин               | Английский        | Значение                                                                                                                                               |
| -------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Владелец             | owner             | Единственный пользователь календаря, задан заранее. Публикует типы событий и доступное время, смотрит список предстоящих встреч. Без личного кабинета. |
| Гость                | guest             | Человек, записывающийся на звонок. Заходит без регистрации.                                                                                            |
| Тип события          | event type        | Предложение владельца: id (slug), название, описание и длительность. Слоты такого типа длятся указанное время. В интерфейсе допустимо «тип встречи».   |
| Слот                 | slot              | Свободный интервал для записи: момент старта плюс длительность выбранного типа события. Старты идут с фиксированным шагом.                             |
| Бронь, запись        | booking           | Факт занятия слота гостем. Появляется в списке предстоящих встреч владельца.                                                                           |
| Предстоящие встречи  | upcoming meetings | Брони с моментом старта не раньше текущего времени, отсортированные по возрастанию; страница владельца показывает их одним списком.                    |
| Окно записи          | booking window    | Скользящий период 14 календарных дней, внутри которого возможна запись. Начало окна зафиксировано: с завтрашнего дня (см. docs/spec.md).               |
| Часы работы          | working hours     | Интервалы дня, в которые владелец принимает звонки: 09:00–18:00 по понедельникам–пятницам. Зафиксированы в docs/spec.md.                               |
| Часовой пояс         | time zone         | Пояс владельца, в котором публикуются слоты и часы работы: Europe/Moscow. Зафиксирован в docs/spec.md.                                                 |
| Шаг стартов          | slot step         | Интервал между возможными моментами начала встречи: 15 минут, общий для всех типов. Зафиксирован в docs/spec.md.                                       |
| Пересечение          | overlap           | Наложение двух броней по времени. Запрещено, включая частичное наложение броней разных типов.                                                          |
| Стык                 | back-to-back      | Случай, когда следующая встреча начинается в момент окончания предыдущей. Разрешён.                                                                    |
| Двойная бронь        | double booking    | Попытка занять пересекающиеся слоты, в том числе двумя одновременными запросами. Должна отклоняться: интервал занимает одна бронь.                     |
| Контракт API         | API contract      | Описание API на TypeSpec (`contracts/`). Единственный источник правды про маршруты и типы.                                                             |
| OpenAPI-спецификация | OpenAPI spec      | Сгенерированный из контракта файл `contracts/tsp-output/openapi.yaml`. Не редактируется вручную.                                                       |
| Клиентский SDK       | client SDK        | Сгенерированный из OpenAPI TypeScript-код в `apps/frontend/src/api-client`. Фронтенд ходит в API только через него.                                    |

## Сценарий в двух словах

Владелец заводит типы событий. Гость выбирает тип, видит свободные слоты в
окне записи (14 дней с завтрашнего дня, часы работы 09:00–18:00 Пн–Пт,
Europe/Moscow, шаг стартов 15 минут), занимает один слот бронью. Бронь без
пересечений с уже занятыми интервалами попадает в список предстоящих встреч
владельца.
