# 4. Тестирование фронтенда: Vitest + Testing Library + jsdom

Дата: 2026-10-30
Статус: Принято

## Контекст

Шаг «главная страница» требует тестов на UI. Бекенд уже тестируется Vitest
(`app.request()` без порта). Нужен способ проверять React-страницы так,
чтобы тесты попадали в общий `npm run check` и CI.

## Решение

- Vitest с конфигурацией `projects` в корне: проект `backend`
  (environment `node`) и проект `frontend` (environment `jsdom`).
- Компонентные тесты на [@testing-library/react](https://testing-library.com/):
  запрашиваем элементы по ролям (`getByRole`), как их видит пользователь.
- Общие обёртки: `renderWithProviders` (MantineProvider + MemoryRouter) в
  `src/test-utils.tsx`; стабы `matchMedia` и `ResizeObserver` в
  `src/test-setup.ts` (jsdom их не реализует, Mantine без них падает).

Альтернативы: happy-dom (быстрее, но jsdom совместимее с Mantine) и
Playwright e2e (проверяет приложение целиком в настоящем браузере, но
дороже в поддержке). Сквозной браузерный сценарий запланирован отдельным
тикетом (issue #7 в исходном проекте 386); если e2e станет постоянной практикой,
его подключение оформим отдельным ADR.

## Последствия

- Тесты страниц быстрые и идут в каждой проверке (`npm test`).
- Рендер Mantine-компонентов в jsdom требует стабов: новые браузерные API,
  которые использует библиотека, добавляются в `test-setup.ts`.
- Тесты не проверяют визуал и реальные сетевые запросы: SDK мокается на
  уровне модуля, когда страницы начнут вызывать API.
