# 1. Стек: TypeScript-монорепо, Hono, React + Vite + Mantine

Дата: 2026-10-30
Статус: Принято

## Контекст

Учебный сервис «Календарь звонков»: владелец публикует типы встреч, гость
бронирует слоты. Курс рекомендует TypeScript и Vite; обязательна цепочка
TypeSpec → OpenAPI → клиентский SDK для языка фронтенда. Разработка идёт на
Windows, проект деплоится в облако. Стек выбирается один раз и надолго.

## Решение

- Монорепо на npm workspaces: `apps/backend`, `apps/frontend`; общий
  корневой `package.json` со скриптами проверок.
- Backend: Node.js + TypeScript + [Hono](https://hono.dev/).
- Frontend: React 19 + Vite + [Mantine](https://mantine.dev/).

Альтернативы для бекенда: Fastify (зрелее экосистемой, но типизация роутов
тяжелее связывается с готовым OpenAPI-контрактом) и Express (устаревший API
без типизации). Hono выбран за web-стандартные Request/Response, встроенный
CORS и тестирование HTTP через `app.request()` без запуска порта.

Альтернатива для UI: shadcn/ui (гибче, но Tailwind-настройка и сборка
компонентов руками). Mantine даёт готовые компоненты (формы, календарь),
которые понадобятся на шаге бронирования, и минимум настройки.

## Последствия

- Один TypeScript-проект на обе части, общий `npm run typecheck`.
- Для dev-запроса фронтенда (:5173) к бекенду (:3000) нужен CORS: включён
  через встроенный `hono/cors`.
- Клиентский SDK генерируется под TypeScript без дополнительных адаптеров.
