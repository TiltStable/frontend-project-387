# 2. Контракт-first: TypeSpec → OpenAPI → клиентский SDK

Дата: 2026-10-30
Статус: Принято

## Контекст

Задание требует: контракт на TypeSpec, сгенерированная из него
OpenAPI-спецификация и клиентский SDK для фронтенда. Серверный генератор
TypeSpec для JS/TS (`@typespec/http-server-js`) находится в alpha, полагаться
на него нельзя.

## Решение

- Контракт живёт в `contracts/*.tsp`, компилируется `npm run contract:build`
  (`tsp compile`) в `contracts/tsp-output/openapi.yaml`.
- Спецификация и SDK коммитятся в репозиторий: сборка не зависит от
  генераторов, изменения контракта видно в diff.
- SDK генерируется `npm run client:generate`
  ([@hey-api/openapi-ts](https://heyapi.dev/), версия запинена `-E`) в
  `apps/frontend/src/api-client`. Фронтенд ходит в API только через SDK.
- Бекенд реализуется по контракту вручную и проверяется тестами; совпадение
  маршрутов с контрактом контролируется на этапе фич.
- Сгенерированные пути (`contracts/tsp-output/**`,
  `apps/frontend/src/api-client/**`) исключены из format-гейта oxfmt: вывод
  эмиттеров не должен ломать проверки.

## Последствия

- Любое изменение API начинается с контракта, затем регенерация и
  реализация: `contract:build` → `client:generate` → код.
- hey-api 0.99 использует JS API компилятора TypeScript, которого нет в
  TypeScript 7: `typescript` запинен на `^5.9` во всём монорепо. Если hey-api
  начнёт поддерживать TS 7, пин можно снять.
- Конфликт «регенерация делает репозиторий красным» закрыт исключениями в
  `.oxfmtrc.json`, а не форматированием генератов.
