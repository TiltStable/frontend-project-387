# Спецификация: бронирование звонков (Design First)

Дата: 2026-10-30. Статус: согласована (карта решений закрыта, см. трекер).
Термины: [GLOSSARY.md](../GLOSSARY.md). Ограничения приложения: [README](../README.md).

## 1. Роли

- **Владелец календаря** — один, задан заранее, без авторизации и кабинета.
  Заводит типы событий и смотрит список предстоящих встреч.
- **Гость** — записывается без регистрации и входа.

## 2. Пользовательские истории

- **US-1** Владелец создаёт тип события: id (slug), название, описание,
  длительность в минутах.
- **US-2** Гость открывает страницу записи и видит виды брони: название,
  описание и длительность каждого типа события.
- **US-3** Гость выбирает тип события и видит свободные слоты на ближайшие
  14 дней.
- **US-4** Гость бронирует свободный слот. При попытке занять занятое время
  видит понятное сообщение о конфликте.
- **US-5** Владелец видит страницу предстоящих встреч: брони всех типов
  событий в одном списке.

## 3. Принятые решения (полная карта — в трекере)

| Вопрос                 | Решение                                                                                                                     |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Окно записи            | 14 календарных дней, начинается с завтрашнего дня                                                                           |
| Рабочие часы владельца | 09:00–18:00, понедельник–пятница                                                                                            |
| Часовой пояс           | Europe/Moscow (UTC+3, без перевода часов)                                                                                   |
| Шаг стартов            | 15 минут, общий для всех типов событий                                                                                      |
| Длительность слота     | Равна длительности выбранного типа события                                                                                  |
| Хранение               | Память процесса через интерфейс репозитория; перезапуск сбрасывает данные (оговорка в README); замена на БД не меняет домен |
| id типа события        | Задаёт владелец (slug `[a-z0-9-]`), конфликт id: 409                                                                        |
| id брони               | Генерирует сервер (UUID)                                                                                                    |
| Данные гостя           | Не собираются (минимальный скоуп, расширяемо позже)                                                                         |
| Формат времени в API   | ISO 8601 с офсетом `+03:00`; границы дней считаются в Europe/Moscow                                                         |
| Префикс маршрутов API  | `/api/*` (исключение: `GET /health` из каркаса)                                                                             |

## 4. Правила окна и занятости

Слот доступен для типа события длительностью `d` минут, если:

1. Дата слота входит в окно: от завтрашнего дня до завтра+13 включительно
   (14 календарных дней по Europe/Moscow).
2. День недели: понедельник–пятница.
3. `09:00 <= start` и `start + d <= 18:00` того же дня (Moscow).
4. Старт кратен 15 минутам.
5. Интервал `[start, start + d)` не пересекается ни с одной существующей
   бронью. Примыкание разрешено: слот, начинающийся в момент окончания
   предыдущей встречи, доступен.
6. Конкурентность: из двух одновременных запросов на пересекающиеся
   интервалы успешен ровно один, остальные получают 409.

Пример: существует бронь 10:00–11:00. Запись 10:30–11:00 отклоняется (409),
запись с 11:00 допустима.

## 5. API

Ошибки: `400` — невалидные данные (формат, диапазон, сетка стартов, окно),
`404` — тип события не найден, `409` — конфликт занятого времени/id.

### GET /api/event-types

`200`:

```json
[
  {
    "id": "intro-call",
    "title": "Знакомство",
    "description": "Короткий звонок",
    "durationMinutes": 15
  }
]
```

### POST /api/event-types

Запрос: `{ "id": "intro-call", "title": "Знакомство", "description": "Короткий звонок", "durationMinutes": 15 }`.

`201` — созданный тип. `400` — id не slug, `title` пустой,
`durationMinutes` вне 1..480. `409` — id уже занят.

### GET /api/available-slots?eventTypeId={id}

`200`:

```json
{
  "eventTypeId": "intro-call",
  "durationMinutes": 15,
  "windowFrom": "2026-10-31",
  "windowTo": "2026-11-13",
  "slots": ["2026-11-02T09:00:00+03:00", "2026-11-02T09:15:00+03:00"]
}
```

Окно календарное и включает выходные (31.10 суббота — 13.11 пятница), но
слотов в субботу и воскресенье нет: первый рабочий день окна здесь —
понедельник 02.11.

`404` — тип не найден. `slots` — доступные старты по правилам раздела 4.

### POST /api/bookings

Запрос: `{ "eventTypeId": "intro-call", "start": "2026-11-02T09:00:00+03:00" }`.

`201`:

```json
{
  "id": "uuid",
  "eventTypeId": "intro-call",
  "eventTypeTitle": "Знакомство",
  "start": "2026-11-02T09:00:00+03:00",
  "end": "2026-11-02T09:15:00+03:00"
}
```

`400` — `start` не ISO-дата, не кратен 15 минутам, вне окна или рабочих
часов. `404` — тип не найден. `409`:

```json
{ "code": "SLOT_TAKEN", "message": "Это время уже занято. Выберите другой слот." }
```

### GET /api/meetings

Предстоящие брони всех типов (`start >= now`), сортировка по возрастанию.
`200`:

```json
[
  {
    "id": "uuid",
    "eventTypeId": "intro-call",
    "eventTypeTitle": "Знакомство",
    "start": "2026-10-31T09:00:00+03:00",
    "end": "2026-10-31T09:15:00+03:00"
  }
]
```

## 6. Границы тестирования

- **Прямые запросы к API** (Vitest, in-process `app.request()`): happy path
  каждой истории; примыкание разрешено; пересечение отклоняется (409); два
  одновременных запроса на один слот дают ровно один 201 и один 409;
  валидации 400/404; окно: нет слотов сегодня и раньше завтра, ровно
  14 календарных дней; выходные исключены; сетка стартов кратна 15 минутам.
- **Браузерный сценарий с настоящим сервером** (Playwright против
  поднятых backend + frontend): гость открывает страницу записи, выбирает
  тип, видит слоты, бронирует, слот исчезает, повторная попытка показывает
  понятный конфликт; владелец видит новую бронь в списке встреч.
- **Юнит-границы**: вычисление доступных слотов (чистая функция) и
  определение пересечения интервалов.

Реализация каждой границы закреплена за тикетами в трекере; e2e-сценарий —
отдельный тикет.
